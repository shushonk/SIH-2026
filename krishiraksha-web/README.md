# KrishiRaksha Web Frontend

A working single-page app (plain HTML/CSS/JS, no build step) that calls the real backend API — every button here does something real, nothing is scripted/hardcoded.

## Run it

1. Start the backend first (see `../krishiraksha-backend/README.md`):
   ```bash
   cd ../krishiraksha-backend
   pip install -r requirements.txt
   uvicorn app.main:app --reload --port 8000
   ```
2. Serve this folder (any static server works):
   ```bash
   cd krishiraksha-web
   python3 -m http.server 5500
   ```
3. Open `http://localhost:5500` in your browser.

If your backend runs somewhere other than `localhost:8000`, either edit `API_BASE` at the top of `app.js`, or set it before load by adding to `index.html`:
```html
<script>window.KRISHIRAKSHA_API_BASE = "https://your-backend-url";</script>
```

## Suggested demo flow (matches the project's demo script)

1. **Farmer view** — select Field 104, check "Close-up of leaf underside," submit scan → see the AI differential diagnosis.
2. **Expert view** — copy the `observation_id` from the pending list, confirm as Early Blight / High severity → see risk score + alerts fire.
3. **Farmer view** — switch back, check the Alerts panel for Field 218 or 301 to see the regional alert with cure info.
4. **Officer view** — see the priority queue and hotspot map update; submit a sensor reading; log an intervention.
5. **Farmer view** — submit the follow-up scan using the `followup_id` generated by the intervention, see the outcome interpretation.

## What's real vs not yet built

- Every API call is real — this isn't mock data, it's live requests to the FastAPI backend.
- **Geospatial hotspot map is now a real Leaflet map** with actual OpenStreetMap tiles, colored circle markers by risk level, and click-to-popup details — not a placeholder SVG anymore.
- UI includes real interaction animations: a sliding role-switch indicator, animated confidence bars, a count-up risk score, staggered card/list entrance transitions, skeleton loading states, and button spinners during requests — these are functional feedback, not just decoration.
- Image upload is simulated (a text filename field) rather than an actual file upload — the backend doesn't yet run real image inference, so a real upload button wouldn't add functionality yet.
- No authentication/login — anyone can act as any role by clicking the role switcher. Add real auth before this goes anywhere near production.
